## 1. 技术选型（评审已确定）

**结论：Tauri 2 + Vue 3 + TypeScript（前端）+ Rust（后端核心）。**

| 维度 | Tauri 2 + Vue 3（选定） | Electron + Vue | Qt/C++（Strawberry 类） |
|---|---|---|---|
| 安装包 | ~10MB | ~85MB | ~25MB |
| 空闲内存 | ~80–120MB | ~200MB | ~60MB |
| 音频解码 | WebView2（Chromium 内核，格式覆盖一致） | Chromium | GStreamer 强但绑定复杂 |
| 元数据生态 | Rust `lofty`（ID3/Vorbis/FLAC/M4A/APE 标签） | `music-metadata` | TagLib |
| 系统集成 | 托盘/自启动/单实例/更新/全局快捷键均有官方插件；SMTC 需 windows-rs 小量自研 | MediaSession 原生齐备 | 全部自研 |
| 单人迭代效率 | 中高（需基础 Rust） | 高 | 低 |

选型理由与备选方案的完整对比见 [ADR-0001](./决策记录/0001-技术选型-Tauri2+Vue3.md)。

## 2. 总体架构

### 2.1 窗口拓扑

| 窗口 | label | 说明 |
|---|---|---|
| 主窗口 | `main` | 三区布局，播放状态的唯一事实源 |
| 迷你悬浮窗 | `mini-overlay` | 动态创建/销毁，置顶透明无边框，见 §6 |

### 2.2 架构图

```
┌─ 主窗口 main（Vue 3 Renderer）──────────────────────────┐
│  views / components / stores(playerStore=唯一事实源)      │
│  services/（invoke 封装，统一错误）                       │
│  <audio> 播放 + Web Audio（EQ，M3）                      │
└──────┬───────────────┬─────────────────────────────────┘
       │ invoke（命令）  │ emit / listen（事件）
┌──────▼───────────────▼─────────────────────────────────┐
│ Rust 核心（src-tauri）                                    │
│  commands/   library/(扫描·lofty·notify)  db/(rusqlite)  │
│  models/  error.rs(AppError)  tray/  overlay/           │
└──────┬─────────────────────────────────────────────────┘
       │
   SQLite(曲库)  app_data/covers/(封面缓存)  文件系统(音频)
```

### 2.3 状态同步原则

1. **播放状态唯一事实源是主窗口的 playerStore**；Rust 在 M0–M2 不持有播放状态
2. playerStore 每次变更 `emit("playback:changed", payload)` 广播；迷你窗监听渲染
3. 迷你窗/托盘的用户操作以事件回流到主窗口执行（见 §5、§6）
4. M2 引入 SMTC 时，由主窗口将状态转发给 Rust（command `smtc_update`），Rust 只做系统桥接

## 3. 播放引擎

- **M0–M2**：renderer `<audio>` 元素，本地文件经 Tauri asset 协议（`convertFileSrc`）喂入；播放状态机在 playerStore
- **M3**：EQ 用 Web Audio API（`MediaElementSource` + BiquadFilter 链，可旁路）；输出设备选择用 `audio.setSinkId()`（WebView2 支持）
- **gapless（M4 决策点）**：若双 `<audio>` 预加载方案无法达标，再评估 Rust `rodio` 输出后端

## 4. 数据模型（SQLite）

存储位置：`%APPDATA%/TinyMusic/db.sqlite3`；迁移用 `PRAGMA user_version` + 顺序迁移脚本；M1 起搜索用 FTS5 虚表。

| 表 | 关键字段 |
|---|---|
| tracks | id, path(唯一), title, artist_id, album_id, track_no, disc, duration, bitrate, sample_rate, bit_depth, genre, year, cover_hash, mtime, size, created_at |
| albums | id, name, artist, year, cover_hash |
| artists | id, name |
| folders | id, path, enabled（曲库来源目录） |
| playlists | id, name, created_at |
| playlist_tracks | playlist_id, track_id, position |
| favorites | track_id, created_at |
| play_history | id, track_id, played_at（最常播放由聚合查询得出，不冗余计数） |
| smart_playlists | id, name, rules(JSON), track_limit, created_at（M4：规则式智能歌单，列表实时生成不物化） |
| settings | key, value(JSON) —— 含迷你窗位置/透明度/锁定态、音量、播放模式、上次曲目 |

去重以 `path` 为主键；`mtime + size` 用于增量扫描判断；封面缓存键为文件内容 hash。

刮削（M4）：封面命中后入 `covers/` 缓存并按需写回音频文件；歌词命中后复用 `tracks.lyrics` 列与同名 `.lrc` 文件通道；专辑信息直接更新 tracks/albums 字段。不新建在线数据缓存表，刮削结果与本地元数据同源。

## 5. IPC 规范

- Command 命名 `动词_名词`（snake_case）；输入输出类型由 tauri-specta 自动生成 TS 绑定，**禁止手写重复类型**
- 列表类 command 一律分页 + 排序参数；统一错误枚举 `AppError`（thiserror + serde）序列化到前端 toast

| Command | 说明 |
|---|---|
| `folder_add` / `folder_remove` / `folder_list` | 曲库来源目录管理 |
| `library_rescan` / `library_rebuild` | 全量重扫 / 重建曲库 |
| `tracks_query(page, sort, filter)` | 歌曲分页查询 |
| `albums_query` / `artists_query` / `folder_tracks` | 视图查询 |
| `search(q)` | 即时搜索（FTS5，M1） |
| `playlist_create/rename/delete/add_tracks/remove_tracks/reorder` | 歌单 CRUD |
| `favorite_toggle(track_id)` | 收藏 |
| `history_add(track_id)` | 播放入库（节流） |
| `cover_url(hash)` | 封面缓存 URL |
| `settings_get(key)` / `settings_set(key, value)` | 设置读写 |
| `overlay_show` / `overlay_hide` / `overlay_set_locked(bool)` | 迷你悬浮窗生命周期与穿透切换 |
| `smtc_update(state)`（M2） | 主窗口 → Rust，转发播放状态给 SMTC |
| `folder_tracks(folder_id)`（M4） | 文件夹视图曲目列表 |
| `smart_playlist_create/update/delete/list`、`smart_playlist_tracks(id)`（M4） | 智能歌单 CRUD 与实时列表查询 |
| `tag_update(track_id, fields)`（M4） | 标签写回源文件并同步曲库 |
| `scrape_album/scrape_track(track_id, source?, query?)` / `scrape_lyrics(track_id, query?)` + `scrape_apply_*`（M4，0.6.1 多站点增强） | 在线刮削（手动触发返回候选，确认后落库）；source ∈ iTunes/Deezer/MusicBrainz（None=合并去重），query=自定义检索词（覆盖标签元数据；歌词走 LRCLIB q 模糊匹配）；MusicBrainz 仅专辑模式，1 req/s 限速 |
| `tracks_all()`（M4 后补） | 一键播放整库（默认排序一次取全） |
| `tag_update_batch(track_ids, patch)`（M6） | 批量标签写回（单事务，返回成功/失败计数） |
| `duplicates_scan()` / `duplicate_resolve(keep_id, remove_ids)`（M6） | 重复曲目分组查询 / 清理（源文件移入回收站） |
| `backup_export(path)` / `backup_restore(path)`（M7） | 全量备份导出与恢复（JSON，按路径匹配曲目，未命中报告） |
| `autostart_set(enabled)`（M7） | 开机自启开关 |
| `global_shortcut_set(action, shortcut)`（M7） | 播放控制类全局快捷键换绑（失败回滚） |
| `window_state`（settings 键，M7） | 主窗口尺寸位置记忆（启动恢复 + 显示器钳制） |

| Event | 方向 | 说明 |
|---|---|---|
| `scan:progress` / `scan:done` | Rust → 主窗口 | 扫描进度/完成 |
| `library:changed` | Rust → 主窗口 | 文件监听触发曲库更新 |
| `playback:changed` | 主窗口 → 所有窗口 | 播放状态广播（track 摘要、is_playing、mode） |
| `overlay:command` | 迷你窗 → 主窗口 | 迷你窗控制指令（play/pause/next/prev/close） |
| `tray:action` | Rust → 主窗口 | 托盘菜单动作 |

## 6. 迷你悬浮播放器技术方案（M2，P0）

### 6.1 窗口配置

动态创建的 WebviewWindow，路由 `/overlay`，同一时刻仅一个实例：

```jsonc
{
  "label": "mini-overlay",
  "url": "/overlay",
  "width": 352, "height": 198,        // 320×180 基础上放大 10%
  "decorations": false,
  "transparent": true,
  "alwaysOnTop": true,
  "skipTaskbar": true,
  "focusable": false,                  // Windows: WS_EX_NOACTIVATE，不抢焦点
  "resizable": false,
  "shadow": false
}
```

默认位置：`primary_monitor()` 计算右上角停靠（距上/右边缘 16px）；恢复持久化位置后经 `clamp_into_monitor` 按当前显示器边界 + 16px 逻辑边距钳制（防窗口尺寸/显示器变更后旧坐标出屏）。Win11 下窗口创建后经 `DwmSetWindowAttribute` 做两件事：`DWMWA_WINDOW_CORNER_PREFERENCE=ROUND` 原生圆角合成（规避 CSS 投影在浅色桌面圆角处露出灰遮罩，前端不用外投影）；`DWMWA_BORDER_COLOR=NONE` 去掉系统自动描边（浅色主题下是白色，且画在窗口边缘、比前端 12px 卡片圆角更靠外，会在四角透明缺口悬空露出白色像素），描边改由前端 1px 暗色发丝线承担。

### 6.2 鼠标穿透与悬停检测（核心需求）

- 穿透：`window.set_ignore_cursor_events(true)`（Windows 底层对应 `WS_EX_LAYERED | WS_EX_TRANSPARENT`，事件直达下层窗口）
- **锁定态（默认）= 穿透开启**；调整态关闭穿透
- 切换途径：托盘菜单「调整迷你播放器」、全局快捷键（**可配置**，settings"overlay"键 `shortcut` 字段，默认 `Ctrl+Alt+M`；`overlay_set_shortcut` 运行时换绑：解绑旧键→注册新键→持久化，失败回滚）、command `overlay_set_locked`
- 拖动前置条件：`data-tauri-drag-region` 触发的 `start_dragging` 属 core:window 插件命令，受 ACL 管控——capability 需显式含 `core:window:allow-start-dragging`（默认集只有只读操作）
- 悬停检测：穿透态收不到任何鼠标事件、CSS `:hover` 失效——`spawn_overlay_watcher` 以 150ms 轮询光标（`cursor_position` vs 窗口矩形），变化时经 `overlay:state` 推送 `hover` 字段；调整态由前端 CSS `:hover` 即时驱动，两者共用同一套显隐视觉
- 调整态 10s 无操作自动回锁（同 watcher 循环驱动，避免前端常驻定时器）；**悬停视为持续操作**——光标停留在卡片上不回锁，离开后 10s 才回锁

### 6.3 交互与拖动

- 显隐模型：未悬停整卡不透明、仅显示封面；悬停时封面层按设置透明度（默认 0.6）变透明，浮现渐变遮罩、曲目信息、控制按钮与底缘进度条——调整态 `:hover` 即时生效且可操作，锁定态经 watcher `hover` 字段驱动同样视觉（内容压暗至 0.75 示意不可操作）
- 调整态：全卡 `data-tauri-drag-region` 拖动（封面/文字/渐变均可抓取），控制按钮（播放/暂停、上一首/下一首、关闭）正常响应
- 拖动结束/关闭时保存位置到 settings 表
- 透明度：作用于悬停态的封面层 alpha（0.3–0.9），设置页滑杆调节，即时生效

### 6.4 状态同步

```
主窗口 playerStore 变更 ──emit playback:changed──▶ mini-overlay 渲染更新
mini-overlay 控制操作(调整态) ──emit overlay:command──▶ 主窗口执行并回推状态
托盘/全局快捷键 ──Rust──▶ overlay_set_locked 切换穿透态
```

迷你窗是**纯薄镜像**：不持有状态、不直接操作播放器，全部经事件回流主窗口。

### 6.5 已知约束

- 穿透态下无法悬停预览或直接操作迷你窗（属预期，符合"不打扰"原则）
- 透明窗口在个别显卡驱动下可能出现 WebView2 渲染异常 → 设置页提供"关闭透明"降级开关
- `alwaysOnTop` 不保证盖住其他置顶窗口与全屏独占应用（属 OS 限制，不做特殊处理）

## 8. 编码规范（后续编码必须遵守）

- **TypeScript**：`strict`；Vue 组合式 API `<script setup>`；组件 PascalCase、组合式函数 `useXxx`、store 命名 `useXxxStore`；ESLint + Prettier 强制；`services/` 之外禁止直接 `invoke`；**包管理统一使用 npm**（`npm install / npm run dev / npm run build`，禁止混用 pnpm/yarn，仅提交 package-lock.json）
- **Rust**：rustfmt + clippy（warning 视为错误）；错误统一 `thiserror` → `AppError`；请求路径禁止 `unwrap/expect`；扫描、解析、DB 写入在独立线程（`tauri::async_runtime`），禁止阻塞主线程
- **Git**：Conventional Commits（feat/fix/docs/refactor）；`main` + 功能分支；每个里程碑打 tag（自 v0.1.0 起）；重大技术决策必须新增 `docs/决策记录/ADR-xxxx`
- **测试**：Rust 单测覆盖元数据解析/去重/迁移；Vitest 覆盖 stores 与纯函数（LRC 解析器必须独立可测）；E2E 于 M2 后视情况引入

## 9. 性能工程要点

扫描在独立线程 + `scan:progress` 事件化；批量事务入库；封面抽取后缩至 256px 存 webp 缓存；虚拟列表；FTS5 搜索；启动懒加载（曲库列表就绪前不加载封面）；tauri-plugin-single-instance 防多开。

## 10. 打包与分发

- tauri bundler → NSIS 安装包（Windows）；图标经 `tauri icon` 生成全套
- 版本号：`0.x.y`，里程碑对应 `0.1/0.2/0.3/0.4`
- 自动更新：tauri-plugin-updater（经 2026-10-01 评审决议缓期：需更新源与签名基础设施，就绪后立项，见功能设计文档 §5 远期池）
