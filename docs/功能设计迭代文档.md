# TinyMusic 功能设计迭代文档

> 版本：v1.0（评审通过）　日期：2026-09-27　状态：**生效**，作为后续所有编码的功能依据
> 配套文档：[技术设计文档](./技术设计文档.md) · [决策记录 ADR-0001](./决策记录/0001-技术选型-Tauri2+Vue3.md)

## 1. 产品定位

TinyMusic 是一款极简、快速、无打扰的**本地桌面音乐播放器**。面向本地音乐收藏用户，只做"把本地音乐放好、放对"：不做流媒体、不做账号、不做社交。

典型用户场景：

- 我有一批本地音乐文件（MP3/FLAC 等），导入文件夹后立刻能播放，界面干净、无推荐无广告；
- 我在工作时，希望播放器缩成一张半透明小卡片悬浮在屏幕右上角，**完全不妨碍**我对下层窗口的鼠标操作；
- 我是键盘党：媒体键 + 快捷键能完成绝大多数操作。

## 2. 设计原则

1. **极简**：三区布局（左侧导航 + 中部内容 + 底部播放条），无信息流、无推荐、无广告
2. **快**：冷启动 ≤ 2s，万首曲库滚动流畅，所有耗时操作不阻塞 UI
3. **键盘友好**：全功能快捷键 + 系统媒体键
4. **数据自治**：全部数据存本地，可导出（JSON / M3U8），卸载不残留
5. **增量交付**：每个里程碑结束都是可日常使用的完整产品
6. **不打扰**：任何悬浮/置顶形态（迷你播放器等）默认不接收鼠标输入（穿透）、不抢占焦点，永远不干扰用户操作

## 4. 核心交互设计

### 4.1 主窗口布局

三区结构：

```
┌────────┬──────────────────────────────┐
│ 左侧导航 │  中部内容区（列表 / 封面墙）      │
│ 视图切换 │                              │
│ 歌单列表 │                              │
├────────┴──────────────────────────────┤
│ 底部播放条：封面│歌名-歌手│控制│进度│音量│模式│迷你模式│
└───────────────────────────────────────┘
```

### 4.2 迷你悬浮播放器（P0，v1.0 评审新增）

**形态**（对齐产品参考截图）：

- 一张**置顶、半透明**的悬浮卡片：封面 + 歌名 + 歌手；默认尺寸约 320×180，提供两档尺寸可选
- 默认停靠**屏幕右上角**（距上/右边缘 16px），可拖动到屏幕任意位置，位置持久化
- 透明度可调：30%–90%，设置页调节，即时生效
- 不出现在任务栏、不夺取焦点、同一时刻仅一个实例

**两种状态**：

| 状态 | 表现 | 鼠标行为 |
|---|---|---|
| 锁定态（默认） | 纯展示，实时跟随播放状态 | **完全穿透**：点击/拖拽/滚轮全部作用于下层窗口，播放器绝不拦截用户操作 |
| 调整态 | 显示拖拽手柄与播放控制按钮（播放/暂停、上一首/下一首） | 正常交互，可拖动位置 |

**状态切换**：

- 托盘菜单「调整迷你播放器」或全局快捷键 `Ctrl+Alt+M` 进入调整态；10 秒无操作自动回到锁定态；再次按 `Ctrl+Alt+M` 立即回锁
- 入口：主窗口播放条「迷你模式」按钮 / 托盘菜单「显示迷你播放器」开关

**验收标准（M2）**：

1. 锁定态下，在迷你窗区域内点击/拖拽/滚动，下层窗口正常响应（以浏览器、资源管理器实测通过）
2. 拖动后的位置重启后保留；透明度设置即时生效
3. 切歌/暂停状态 ≤ 500ms 反映到迷你窗
4. 置顶于普通窗口之上；不出现在任务栏；不夺取键盘焦点

### 4.3 快捷键

| 键 | 行为 | 作用域 |
|---|---|---|
| Space | 播放/暂停 | 应用内 |
| ←/→ | 快退/快进 5s | 应用内 |
| Ctrl+←/→ | 上一首/下一首 | 应用内 |
| ↑/↓ | 音量 ±5% | 应用内 |
| Ctrl+F | 聚焦搜索 | 应用内 |
| Enter | 播放选中项 | 应用内 |
| L | 收藏/取消 | 应用内 |
| M | 静音 | 应用内 |
| Ctrl+1/2/3 | 切换主视图 | 应用内 |
| Esc | 关闭弹层/清除搜索 | 应用内 |
| **Ctrl+Alt+M** | **迷你悬浮播放器：锁定⇄调整态切换** | 全局 |
| 媒体键 | 播放/暂停/上下曲 | 全局（M2 起随 SMTC 集成） |

## 5. 迭代路线

### M0 — 可用骨架（播放核心）　工作量：中

- 范围（严格限定）：选择文件夹 → 扫描 → 歌曲列表 → 双击播放；底部播放条全套控制；播放模式；重启后恢复曲库与播放状态；扫描/解析失败跳过且不卡 UI
- 验收：
  - 1000 首扫描 ≤ 10s，扫描全程 UI 不卡顿
  - MP3/FLAC/M4A/OGG 播放正常
  - 重启后曲库、音量、上次曲目与进度恢复

### M1 — 曲库与歌单体验　工作量：中

- 范围：专辑/艺人/收藏视图、封面墙、搜索、播放列表 CRUD、播放队列（下一首播放/拖拽排序）、增量扫描（文件监听）
- 验收：
  - 10,000 首列表滚动不掉帧（虚拟列表）
  - 搜索响应 ≤ 100ms
  - 文件增删改后曲库 5s 内自动同步

### M2 — 歌词、系统集成与迷你悬浮播放器　工作量：中

- 范围：滚动歌词（内嵌 + .lrc）、正在播放全屏页、SMTC/媒体键、托盘、三态主题、中英文、**迷你悬浮播放器（本期 P0，设计见 4.2，技术方案见技术设计文档 §6）**
- 验收：
  - 歌词同步偏差 ≤ 200ms
  - 系统媒体浮层显示封面且媒体键可用
  - 主题切换无需重启
  - 迷你悬浮播放器全部验收标准（4.2）通过

### M3 — 音质与效率　工作量：小～中　状态：✅ 已完成（2026-10-01，详见技术设计文档 v2.1）

- 范围：EQ（Web Audio）、输出设备选择、播放倍速、最近/最常播放、M3U8 导入导出（自动更新经 2026-10-01 评审决议缓期，移入远期池）
- 验收：
  - EQ 可开关且各频段生效
  - 切换输出设备中断 ≤ 1s
  - foobar2000 导出的 M3U8 可正常导入
- 遗留：EQ 实际听感与 setSinkId 真机切换待 tauri dev 人工冒烟

### M4 — 曲库与数据进阶　工作量：中　状态：✅ 已完成（2026-10-01，详见技术设计文档 v2.3）

- 范围（2026-10-01 评审通过；updater 经决议移出本期）：
  - **文件夹视图**：按来源目录浏览曲目，补齐功能地图「视图·文件夹」与技术设计文档 §5 预留的 `folder_tracks`
  - **智能歌单（规则式）**：规则条件 = 播放次数 / 最近播放 / 流派 / 年份 / 添加时间，加数量上限（评审确认规则集）；列表实时生成，只读、不可拖拽排序
  - **标签编辑**：单曲编辑标题/艺人/专辑/流派/年份/曲号，lofty 写回源文件（评审确认接受写回），曲库同步；mtime 变化由现有增量扫描自然消化
  - **在线刮削**：封面 / 歌词 / 专辑信息，手动触发（按专辑或单曲），仅元数据、不引入在线音源（对齐 §7 Out of Scope）；歧义匹配需人工确认。刮削方向以**流行日语歌曲（J-Pop）为主**：封面/专辑信息走 iTunes Search **JP 店面优先、US 兜底**，歌词走 LRCLIB（均免鉴权）
- 验收：
  - 文件夹视图按目录正确列出曲目
  - 智能歌单规则修改后列表即时生效，不满足规则的曲目自动进出
  - 标签编辑后源文件与曲库一致，重新扫描不产生重复条目；只读文件给出明确报错
  - 刮削命中后封面/歌词/专辑信息入库并展示；未命中或网络不可用给出明确反馈，且不影响本地功能

### M5 — 逐字歌词　工作量：小　状态：✅ 已完成（2026-10-01，详见技术设计文档 v2.6）

- 范围（2026-10-01 评审通过；桌面歌词经决议不做）：增强型 LRC 字级时间标签 `<mm:ss.xx>` 解析（纯函数 + 单测）、NowPlaying 卡拉OK式逐字高亮
- 验收：
  - 逐字同步偏差 ≤ 200ms（沿用 rAF 直读引擎时间方案）
  - 无字级时间戳的歌词回退逐行滚动，不报错

### M6 — 曲库管理效率　工作量：中　状态：✅ 已完成（2026-10-01，详见技术设计文档 v3.0；版本 0.7.0）

- 范围：
  - **多选与批量标签编辑**：TrackTable 支持 Ctrl/Shift 多选，批量统一设置 艺人/专辑/流派/年份（留空=不改）+ 曲号按列表顺序自动重编；复用 M4 lofty 写回与曲库同步链路，后端批量命令单事务完成
  - **重复曲目检测与清理**：按 归一化标题+艺人+时长±2s+文件大小 分组展示重复组，每组默认保留最早添加的一条；清理时**源文件移入回收站**（评审决议：仅删曲库记录会被增量扫描重新扫回；trash crate 实现、可恢复）
  - **缺失封面批量刮削向导**：专辑视图入口，逐专辑展示 iTunes 候选（JP 店面优先延续），**逐个人工确认**（评审决议，Enter 确认 / Esc 跳过），完成后给 成功/跳过/未命中 统计
- 验收：
  - 批量改 20 首后重扫无重复条目、FTS 可搜新艺人；个别只读文件报错且不影响其余（返回成功/失败计数）
  - 重复分组准确；清理后曲库无该曲目且源文件可在回收站找回
  - 批量刮削向导逐个确认生效，统计数字正确

### M7 — 数据自治与系统集成　工作量：小～中　状态：✅ 已完成（2026-10-02，详见技术设计文档 v3.1；版本 0.8.0）

- 范围（**开机自启经决议暂不做**——2026-10-02 评审，远期池保留）：
  - **全量备份导出/恢复（JSON）**：歌单+智能歌单+收藏+播放历史+设置 → 单文件导出（备份含格式版本号，settings 排除机器态的 window 键）；恢复为**合并语义**——按路径归一化匹配曲目（大小写/斜杠不敏感，复用 M3U8 归一化），同名歌单追加未命中曲目、收藏/历史去重（同曲同刻）、智能歌单同名跳过+规则非法跳过不阻断，未命中条目计数报告；恢复后快捷键配置即时重注册、外观设置前端即时重读，无需重启
  - **全局快捷键自定义**：播放/暂停、上一首、下一首、显示/隐藏迷你窗 四个动作；默认全部未绑定，设置页输入+回车换绑、清空+回车解绑；先注册新键成功才解绑旧键并落库（失败旧键保持可用）；播放控制经托盘同款 tray:action 通道回流主窗口
  - **主窗口记忆尺寸与位置**：CloseRequested 与托盘退出前保存（物理坐标+最大化标记），启动恢复（窗口改为默认隐藏，恢复并钳制进显示器后再显示，避免位置跳变；复用 clamp_into_monitor）
  - **拖拽导入**：拖目录/音频文件到主窗口 → 目录直接作为曲库来源、音频文件取其所在目录（曲库以目录为管理单元，可纳入增量监听与删除联动）；已被曲库目录覆盖的候选跳过，全窗拖放遮罩提示 + 结果通知
- 验收：
  - 导出的备份在新环境恢复后 歌单/智能歌单/收藏/设置 完整，未命中曲目有明确报告（单测覆盖 完整恢复/未命中跳过/重复恢复去重/智能歌单跳过 4 场景）
  - 快捷键换绑失败保持旧键可用（先注册后解绑）
  - 窗口位置重启恢复且不出屏；拖拽导入触发扫描并纳入监听

### M8 — 播放品质　工作量：中　（2026-10-01 评审通过）

- 范围：
  - **gapless 无缝播放**：先实测双 `<audio>` 预加载方案（M4 遗留决策点）；不达标再启动 ADR-0002 Rust 解码后端评估
  - **Crossfade 淡入淡出**：Web Audio GainNode 双曲交叉，0–6s 可调、默认关闭
- 验收：
  - 开启 gapless 后曲间停顿 ≤ 100ms（人工听感为主）
  - crossfade 曲线平滑、可开关，与 EQ/倍速共存不冲突
- 评审决议（2026-10-01）：**APE/WMA 暂不支持**（Rust 解码后端评估保留远期池，需要时再启动）；**音量均衡暂不做**（远期池保留）

### M9+ — 远期池（逐项评估）

- **自动更新（updater）**：继续缓期；待签名密钥与更新源基础设施就绪后立项
- **Rust 解码后端评估（ADR-0002）**：gapless 双 `<audio>` 方案不达标时的兜底，以及 APE/WMA 支持（暂不支持，需要时再启动）；评估包体积/内存/工作量后产出 ADR 再立项
- **音量均衡（ReplayGain / EBU R128）**：暂不做（2026-10-01 评审）
- **云备份（云端）**：M7 本地全量备份落地后再评估是否需要云端同步
- 已决议不做（2026-10-01 评审）：桌面歌词、插件系统（参考 MusicFree）
- 已完成移出：迷你播放器进度条（v1.9 已随迷你窗重构实现）、全局快捷键自定义（并入 M7）、本地数据备份（并入 M7）

## 6. 非功能需求

| 类别 | 指标 |
|---|---|
| 启动 | 冷启动 ≤ 2s（M1 起） |
| 资源 | 空闲播放内存 ≤ 150MB；迷你悬浮窗锁定态 CPU 占用可忽略（动画仅用 CSS opacity，避免持续重绘） |
| 体积 | 安装包 ≤ 15MB |
| 格式 | MP3 / AAC(M4A) / FLAC / WAV / OGG(Vorbis+Opus)；APE/WMA 暂不支持（2026-10-01 评审决议，远期池保留 Rust 解码后端评估） |
| 平台 | Windows 10 1809+ / 11 优先；macOS、Linux 在 M3 后评估 |
| 稳定性 | 任何单个文件解析失败不影响整体；曲库损坏可一键重建；扫描/解析不在主线程 |

## 7. 明确不做（Out of Scope）

在线流媒体与音源聚合、账号体系与云同步（云备份除外）、社交与评论、播客与视频、移动端。
